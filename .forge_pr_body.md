## What broke

`agentic_bootstrap`'s sandbox picks a Docker base image via `_choose_base_image`, which used to **always** ask the LLM for a one-word ecosystem guess ("python/node/java/go/rust/c/cpp/c++/unknown") — even for a repo with an unambiguous marker file sitting right there (`pyproject.toml`, `package.json`, `go.mod`, …).

If that one-word reply didn't parse cleanly, the picker silently degraded to `ubuntu:24.04`. That image has no `python`/`pip`, so every subsequent step in the sandbox failed with exit `127` until the agentic bootstrap's step/wall-clock caps were exhausted — a real python repo would burn its whole budget without ever running a test.

## The fix

`_choose_base_image` now checks deterministic marker-file detection **first**, via a new `_detect_ecosystem_deterministic` that reuses the same stack registry `detect_test_stack` already relies on (`stacks.all_stacks()[i].detect(root)`):

- Exactly one stack's markers match → return that image directly, **no LLM call at all**.
- Zero or more than one stack matches (genuinely ambiguous, e.g. a python backend + node frontend at the repo root) → fall back to the LLM tie-breaker, same constrained-menu behavior as before (never a free-form image name a prompt could hallucinate into a pull).

Net effect: a python/node/java/go/rust/C-or-C++ repo with normal markers gets the right base image deterministically, and the LLM is only ever consulted for the actually-ambiguous case.
